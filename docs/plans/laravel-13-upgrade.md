## Context

The site currently runs on `laravel/framework ^12.10` (TALL stack + Filament 4). The
goal is to upgrade to Laravel 13. Per the [official 13.x upgrade guide](https://laravel.com/docs/13.x/upgrade#upgrade-13.0),
the framework estimates ~10 minutes of work, and most documented breaking changes live in
obscure areas. I cross-checked **every** change in the guide against this codebase: the actual
code footprint here is very small — **one** required source edit plus dependency bumps. The
dominant risk is not framework breakage but **third-party package readiness** for Laravel 13.

### 2. `app/Providers/Filament/AdminPanelProvider.php` — CSRF middleware rename (High impact)

This is the only required source edit. Currently (lines ~18 and ~51):

```php
use Illuminate\Foundation\Http\Middleware\VerifyCsrfToken;
// ...
->middleware([
    // ...
    VerifyCsrfToken::class,
])
```

Change both the import and the array reference to:

```php
use Illuminate\Foundation\Http\Middleware\PreventRequestForgery;
// ...
    PreventRequestForgery::class,
```

`VerifyCsrfToken` remains a deprecated alias in 13, so this won't hard-break, but the guide
recommends updating direct references. Note the new middleware also adds `Sec-Fetch-Site`
origin verification — worth a manual smoke test of the Filament admin login/forms after upgrade.

### 3. `config/livewire.php` — Livewire 4 config changes (required)

> Added during execution — not in the original Laravel-13 guide, but required by the Livewire 3→4
> jump that unblocked the upgrade.

**(a) Layout key rename.** Livewire 4 renamed the page-layout config key from `layout` to
`component_layout`. Because Laravel's `mergeConfigFrom` injects the Livewire 4 default
(`component_layout => 'layouts::app'`) into the Livewire-3-era published config, that default wins
over the old `layout` key and `/` fails with *"No hint path defined for [layouts]"*. Fix:

```php
// Before (Livewire 3)
'layout' => 'livewire.app-layout',

// After (Livewire 4)
'component_layout' => 'livewire.app-layout',
```

**(b) `smart_wire_keys` default flip.** Livewire 4 changed the default of `smart_wire_keys` from
`false` (v3) to `true`. This project explicitly sets it back to `false` to preserve the v3
`wire:key` behavior and avoid subtle morph/re-render differences on the existing components:

```php
// Now defaults to true (was false in v3)
'smart_wire_keys' => false,
```

Revisit later if you want to adopt the v4 default (`true`) — it improves Livewire's automatic key
injection, but should be tested against the blog/archive lists that render loops.

### 4. `config/cache.php` — optional hardening (Medium impact, skipped)

The new 13.x skeleton adds `'serializable_classes' => false` to the cache config to harden
against PHP deserialization gadget attacks. This app uses the `database` cache store and stores
no PHP objects, so the secure default is safe. Skipped during execution (no behavioral effect);
add later to stay in sync with the 13.x skeleton if desired:

```php
'serializable_classes' => false,
```

### 5. Cache / session prefix change — no action, but be aware

The 13.x fallback prefixes switched from `_` to `-` separators. This repo's `config/cache.php`,
`config/session.php`, and `config/database.php` **hardcode the old `Str::slug(APP_NAME, '_')…`
pattern explicitly**, so the framework fallback change does not apply and cache keys / the
session cookie name stay stable — existing sessions and cache entries survive the upgrade. Do
**not** blindly copy the 13.x skeleton versions of these three config files, or you'd silently
change key names and log everyone out / cold-start the cache. Leaving them as-is is correct.

## Verification

- **Boot / config**: `php artisan about` and `php artisan optimize:clear` — confirms the app
  boots on Laravel 13 and shows the new framework version.
- **Tests**: `vendor/bin/pest` — the suite is the default scaffold (`tests/Feature/ExampleTest.php`
  hits `/` expecting 200, plus `tests/Unit`). It should stay green; a green run confirms routing,
  Livewire full-page components, and middleware still work. (`RefreshDatabase` is commented out in
  `tests/Pest.php`, so no DB is touched.)
- **Filament admin (CSRF change)**: `composer run dev`, log into `/admin`, and exercise a form
  submit (create/edit a Post or SoldItem) to confirm the new `PreventRequestForgery` middleware
  and its `Sec-Fetch-Site` origin check don't reject legitimate requests.
- **Front-end smoke**: load the homepage, a blog post detail (`/blog/{id}-{slug}`), and an archive
  list page (pagination `->links()` renders) to confirm no regressions.
- **Cache/session continuity**: confirm you are not logged out unexpectedly and cached data
  persists — validates that the prefix decision in §5 held.

## Risks & notes

- **Primary risk = dependency readiness.** Confirmed real: Filament 4, Livewire 3, and the smaller
  packages had no `^13` tags, forcing the Filament 5 / Livewire 4 route.
- The Filament CSRF middleware swap and the Livewire layout-key rename are the two behavioral
  changes worth a manual test; everything else is version metadata or config sync.
